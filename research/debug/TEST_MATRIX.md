## 2. Summary of Findings
1. **Current Test Pass Rate**: **132/132 unit tests (138 total runnable tests including 6 benchmarks)** passing on Windows 11 NTFS native (7.97s), **132/132 unit tests passing under WSL2 `go test -race` with zero data races and zero deadlocks** (16.38s). Clean `go vet ./...` in both environments.
2. **Phase I3 Complete Implementation (SyncModeApproachB)**: Full implementation of Approach B reader snapshots, two-tier reference ownership (`ReaderSnapshot` pins and `SharedReader.refCount`), atomic snapshot swap on flush and compaction, zero-lock SSTable disk reads, 4 cleanup categories (A, B, C, D), Windows NTFS sharing violation prevention with retry backoff, and strict equivalence with Approach A baseline.
3. **Synchronization-Mode Seam (INV-APPROACH-A / D-018)**: Engine provides explicit `SyncMode` (`SyncModeApproachA`, `SyncModeApproachB`) and `CreateManagerWithConfig(cfg)`. Default configuration selects Approach A. Approach B is fully functional and tested.
4. **Flush Failure Precedence & Fail-Stop (INV-FLUSH-FAIL-1 / D-017 / Issue E-010)**: When a flush fails, background worker `flushLoop` halts immediately upon observing `m.flushErr != nil`. Halting prevents subsequent generations from being published out-of-order to active readers, preserving strict chronological order in `m.Frozenmem` and eliminating stale reads, tombstone resurrection, and conflict detection failures.
5. **Memory-Tier Synchronization (INV-SYNC-1 / D-016)**: Active Memtable mutations (`Put`) and lookups (`Get`, `LatestValue`) are serialized exclusively under `Manager.Mu` (`Lock()` for writes, `RLock()` for reads).
6. **Frozen Memtable Immutability (INV-MUTABLE-1)**: Once active Memtable is frozen and appended to `m.Frozenmem`, it is permanently sealed against further mutations. Concurrent lookups under `m.Mu.RLock()` and background worker iteration in `flushToDisk()` are concurrent reads of immutable data, verified race-free.
7. **Zero-Loss Memory-to-Disk Handoff (INV-HANDOFF-1)**: Flushed reader is published and Memtable removed from `m.Frozenmem` within the exact same critical section under `m.Mu.Lock()`.
8. **Acyclic Lock Hierarchy (INV-SYNC-3 / D-028 / D-030)**: Strict hierarchical order `m.compactionMu -> Manager.Mu -> m.snapshotMu -> m.flushQueueMu -> Wal.mu` maintained across all paths. Deadlock freedom validated empirically under saturated conditions.
9. **Durability and Recovery Limitations**: Documented single-file recovery limit in `RecoverFromWAL` (`RISK-002`), unbounded queue memory growth (`RISK-001`), and RAM-only volatility of failed Memtables (`RISK-003`) as open risks for Checkpoint CP1 (`research/design/durability_and_recovery_limitations.md`).
