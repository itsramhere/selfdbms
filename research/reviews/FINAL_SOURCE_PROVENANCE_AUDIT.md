## 1. Executive Summary

During Phase I6.8, an external review identified that all 600 raw JSON trial records generated by the targeted validation campaign recorded:
```json
"git_revision": "unknown_rev"
```
The execution environment `/home/ramst/selfdbms` on native WSL2 ext4 lacked a `.git` metadata repository directory. Consequently, independent automated verification of the precise Git commit that produced the executable `/home/ramst/selfdbms/targeted_runner` was blocked at the metadata layer.

This forensic audit resolved the historical provenance through physical binary inspection, file-by-file cryptographic comparison against candidate Git revisions, and controlled reproducible reconstruction.

### Key Audit Findings:
1. **Preserved Executable Verification**:
   The preserved historical executable `/home/ramst/selfdbms/targeted_runner` has SHA-256:
   `2855b4318d5c574a2d0c3fbf5eb773f3ae7aebd1d0469961db3a9b8e6399832f`, exactly matching historical records.
2. **Root Cause of `"unknown_rev"`**:
   Inspection of `research/experiments/targeted_validation/cmd/main.go` lines 42–49 confirms that `getGitRevision()` executed `git rev-parse HEAD`. Because `/home/ramst/selfdbms` was a standalone directory without `.git`, the command failed, causing the runner to return the fallback string `"unknown_rev"`.
3. **Source Code Identity**:
   Cryptographic comparison across all 71 build-critical source and manifest files confirms that the native source tree in `/home/ramst/selfdbms` is **100% identical under LF normalization** (71/71 files) to historical Git commit `370fd6c5a138321ee3741bb7774e950a30d23587` (and subsequent documentation/data commits `81429fc` and `4a06217`, which contain identical Go source code).
4. **Byte-for-Byte Binary Reconstruction**:
   Executing a clean reconstruction build from `/home/ramst/selfdbms` to an isolated output path (`/tmp/test_runner_from_native`) using Go 1.27.3 produced an executable with:
   - **SHA-256**: `2855b4318d5c574a2d0c3fbf5eb773f3ae7aebd1d0469961db3a9b8e6399832f`
   - **Go Build ID**: `raCgnlKhcejFVErxy8Ge/pSHSnyg97yOboCajV8nD/xtHS_TCzXh93CP88li-A/ax9WzPJrX-5xwTVSUvpn`
   - **GNU Build ID**: `ea953cf6bc0025fd4e351027a7190a8ca9e48772`
   - **Exact Size**: `5,453,058` bytes
   This proves byte-for-byte bit-level identity between the historical executable and the native source code.
5. **Path-Dependency Findings**:
   Rebuilding from an alternate filesystem path (e.g. `/home/ramst/reconstruction_test`) yields a differing binary hash (`a6e045bf37...`) because Go's default build without `-trimpath` embeds the absolute directory path (`/home/ramst/selfdbms/...`) into DWARF debug symbols and pclntab function tables. This independently confirms that the historical binary was compiled specifically within `/home/ramst/selfdbms`.
